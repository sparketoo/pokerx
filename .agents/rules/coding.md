# Coding

## Use clear Hyperf project names
Name tables, columns, classes, methods, routes, parameters, and variables with complete domain words; follow the existing `Controller`, `Request`, `Service`, `Job`, `Vo`, and `Enum` suffixes without redundant qualifiers.

## Follow the current PHP style
Use strict types, typed parameters and return values, braces for control flow, and PHPDoc array shapes for complex arrays; follow neighboring files and run Pint only on files changed for the task.

## Validate Necessity Before Introducing Concepts
Before adding fields, identifiers, states, recovery mechanisms, or dependencies, assess confirmed requirements, existing Hyperf components, and maintenance cost; avoid speculative abstractions.
